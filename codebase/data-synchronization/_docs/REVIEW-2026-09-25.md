# Expense Tracker and synchronization review — 2026-09-25

## Scope

Reviewed daily mobile/browser entry, Apps Script persistence, account/category/transaction/subscription contracts, six account-detail imports, manual job startup, currency acquisition and PostgreSQL extraction. Changes are local code/docs/tests; this review does not deploy the app or run synchronization against configured dev/prod data.

## Findings addressed

| Area | Gap and resulting behavior |
|---|---|
| Refresh and stale selections | A slow earlier refresh could replace newer post-save data. Only the latest requested refresh commits; open row selections follow UUIDs across reorder, and mutation requests carry the expected identity/edit timestamp for server validation. |
| Mobile authentication and forms | Login could remain disabled on a later auth failure or wait indefinitely for location lookup. Recovery and bounded lookup are covered; mobile confirmations remain in cards, controls have usable touch sizes, and delayed suggestions preserve drafts. |
| Transaction entry and export | Invalid target amounts could silently inherit source amounts, and decimal strings could lose precision. Transfers require valid amounts; source decimal text, unchanged timestamps, identity and parent direction are preserved through entry/copy/export. |
| Source validation | Transaction dates, zones and coordinate pairs are checked before writing, including nonexistent/ambiguous DST times. Account timezones and snapshot timestamps follow the same rules. Native Sheet date cells are emitted as wall-time text. |
| Import and transfer invariants | Account imports can no longer bypass immutable financial fields or change locked account/detail rows. Equivalent immutable values retain their original spelling/text. Per-leg transfer edits/deletes/restores cannot create pairs that ledger-extract rejects; delete the child first and restore the parent first. |
| Snapshot balances | Cross-zone transactions could be included before their opening snapshot. Backend balances, frontend replay and balance checks compare actual instants for zoned accounts; blank account zones retain legacy wall-time behavior. |
| Category extraction | Only dynamic hint refreshes previously checked the Sheet before commit. All category writes now check, rolling back the master and both junction sets if the source changed. |
| Account/detail valuation | Currency precision/rate rows could change between valuation and commit. Shared reference locks now last through the source check and commit, and account precision is refreshed for each row. |
| Sync configuration and numeric grammar | Old/misspelled entity names could silently skip work. Invalid configuration fails before job connections; transaction decimals/coordinates reject Python-only spellings that the source app does not accept. |
| Daily currency acquisition | Each currency could use a separately fetched gold close. One shared gold snapshot now anchors a run; provider retries/timeouts are bounded and ambiguous duplicate source dates/headers fail explicitly. |
| Currency persistence | Concurrent rate jobs could interleave, Decimal rounding depended on caller context, and SQL allowed numeric NaN. Jobs take a transaction advisory lock, conversion uses isolated precision, and migration `0006` enforces finite rates and XAU=1. |
| Manual currency startup | Invalid mode/config errors appeared after migrations with little explanation. Preflight validates configuration before migration, and errors expose safe actionable codes. |
| Legacy computed insights | The optional job still uses obsolete fields and a dual-leg model. It fails before live I/O under the current source contract, and the API rejects unversioned legacy payloads. Live browser insights remain available. |
| Development server | The generic repository server listened on every interface and could expose private local files to the LAN. `make app-start` now binds to loopback. |

## Additional findings from the final review

The independent final pass rechecked the working changes above and closed these further gaps:

| Area | Gap and resulting behavior |
|---|---|
| CSV round-trips | Account/transaction imports now parse quoted multiline fields, reject malformed headers visibly, and retain transaction decimal strings. Standalone money-in exports put the amount on the correct side. Transfer export refuses states that its combined-row import format cannot preserve. |
| Import outcomes | File-selection races no longer replace a newer preview. Known partial failures retry only failed rows; malformed results or a lost response cannot be reported as success or blindly resubmitted from the same preview. |
| Mobile connectivity and date filters | Reads and writes have bounded HTTP deadlines without automatic mutation retries. Failed/uncertain saves explain that the outcome must be checked. Date filters use calendar components rather than browser-dependent timestamp parsing. |
| Categories | Source UUID and classification collisions fail before writes, including deleted-key reservations. Referenced classification keys cannot be force-renamed. Direct category Sheet edits now advance source revision and queue synchronization. |
| Detail/source validation | All six detail imports enforce the same boolean, calendar, integer-range, sign, percentage and NUMERIC(38,18) precision constraints as extraction. Cross-language tests compare the executed GAS registry with Python contracts. Unexpected trailing Sheet columns fail before mutation. |
| Beneficiaries and subscriptions | GAS validates complete beneficiary allocations before save. ETL rejects Python-only percentage spellings and non-ASCII subscription amount/day digits, matching the source input grammar. |
| Legacy snapshot cutoff | A browser DST jump could move an earlier wall timestamp beyond a blank-zone account cutoff. The cutoff now compares wall components directly; replay and edit guards agree with GAS. |
| Suggestions | Native amounts from different accounts/currencies no longer share a median. Deleted, invalid, future and unavailable-account movements are excluded. Stable suggestion identities distinguish cards; delimiter-containing names and the monthly due-day window are handled. |
| Currency calendar/startup | Forward-fill generates calendar dates independently of the PostgreSQL timezone, including midnight DST jumps and skipped local dates. The launcher exports the documented default port when it is unset so migrations and runtime use the same configuration. |
| Logging and documentation | Suggestion logs omit payee names; advisor/provider failures expose static error codes instead of raw response/exception text. Mapping docs now describe optional subscription classification and the source-enforced transfer lifecycle order accurately. |

## Boundaries and rollout

- Deploy frontend and GAS together to activate the source and mobile fixes. The next selected currency run applies migration `0006`; invalid existing rates cause migration failure and require explicit review rather than automatic rewriting.
- The app still uses current Sheet rates for display; PostgreSQL ledger valuations use dated rates from currency-rates. Running data-sync does not refresh the app's Rates tab.
- There is no offline mutation queue or end-to-end exactly-once guarantee after a lost HTTP response. Refresh and inspect before retrying a save whose outcome is unknown.
- The transaction CSV export is an import-compatible combined-transfer format, not a full Sheet backup. It rejects transfers whose per-leg lifecycle or other shared fields cannot be represented faithfully; retain the Sheet as the authoritative record.
- PostgreSQL/Sheets writes cannot be globally atomic. Source guards narrow concurrent-edit risk, but the final check-to-acknowledgement race remains; use a quiet editing window.
- Historical rates are required. Exact UTC-date rates for transactions may be absent on crypto weekends; account/detail carry-forward has no maximum age. These remain explicit valuation policies.
- Physical Sheet deletion is not a tombstone. Immutable account changes and conflicting identities require reconciliation; hard-sync cannot infer deleted rows or missing financial facts.
- The optional legacy precomputed-insights implementation is safely blocked, not ported. It must be rebuilt against the current single-leg contract before publishing versioned results.
- No configured dev/prod database, real Sheet, live provider response or physical mobile device was used to certify deployment behavior. Automated fixtures cannot prove live permissions, quotas or device-specific Safari behavior.
