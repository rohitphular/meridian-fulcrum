# Categories — Sheet to database mapping

Source tab: `category_master`, 21 columns. Main destination: `category_master`, 16 columns. The two account-type lists expand into junction tables rather than being copied into text columns. Database audit timestamps are generated by extraction; their names do not mean that Sheet timestamps are copied.

Source contracts: [GAS schema](../../../expense-tracker/api/category-schema.gs), [normalisation](../../../expense-tracker/api/category-utils.gs), [entity requirements](../../../expense-tracker/_docs/categories.md). Implemented mapping: [transform](../transforms/categories.py), [database writer](../database/categories.py), [migration 0003](../migrations/0003_create_categories.py).

**Prerequisite:** apply migrations through 0020 and synchronize [account types](account-types.md) before categories. The account-types source UUID is reused for both junction tables. Existing unmanaged catalog rows may adopt that UUID once with dependent links updated atomically; subsequent syncs preserve it.

**Identity guarantee:** `category_master.id` is always the UUID from the Sheet's `category_master.id`. Creates, retries, updates and restores keep that UUID; both junction tables use it as `category_id`. The extractor never generates a replacement category UUID or writes one back to the Sheet. UUID text may be canonicalised without changing its identity.

Positions are the current GAS registry positions. The extractor reads by header name and resolves acknowledgement columns by their actual position.

## Database-generated columns

The mapping above accounts for 14 directly populated master columns. These two additional master columns complete all 16 `category_master` columns.

| Database column | Type | Source / generation |
|---|---|---|
| `category_master.created_at` | TIMESTAMPTZ NOT NULL | PostgreSQL `now()` at first insert; preserved on retry/update. It is not the source creation time. |
| `category_master.updated_at` | TIMESTAMPTZ NOT NULL | PostgreSQL `now()` on each actionable insert/update, even if content is unchanged. It is not the source edit time. |

## Account-type expansion and complete related-table mapping

GAS accepts configured eligible subtype keys and the shorthand `investment`. For example, `current, savings` becomes two links. `investment` resolves every active or locked, Sheet-managed, successfully synchronized database row whose `account_type_key='investment'`; other tokens match `account_subtype_key`. Legacy underscore hints are accepted only when the corresponding hyphenated subtype exists in that eligible catalog, matching the CSV importer; unknown aliases still fail. Exact eligible keys take precedence. Labels are display text and never used to resolve identity. Unknown, inactive or unsynchronized hints fail the category instead of silently dropping mappings. Blank means no junction rows. A repeated token or repeated resolution does not create duplicate links. In normal-sync, an otherwise in-sync category with an `investment` hint is reprocessed only when its expanded junction IDs no longer match the available investment types. This handles newly synchronized ownership of existing catalog subtypes without requiring hard-sync; disabled category extraction defers reconciliation until its next enabled run.

| Source | Database column | Type | Rule |
|---|---|---|---|
| `category_master.id` | `category_source_account_types.category_id` | UUID NOT NULL | Source category UUID; FK to `category_master.id`. |
| `category_master.source_account_types` | `category_source_account_types.account_type_id` | UUID NOT NULL | Resolved reference row ID, not the token string. |
| `category_master.id` | `category_target_account_types.category_id` | UUID NOT NULL | Source category UUID; FK to `category_master.id`. |
| `category_master.target_account_types` | `category_target_account_types.account_type_id` | UUID NOT NULL | Resolved reference row ID. |

Each junction has only the two listed columns and a composite PK. Master changes and replacement of both junction sets commit in one transaction.

Every category write rechecks the captured Sheet content immediately before commit. A source/header change rolls back the master and both junctions without acknowledging that row; this applies to pending creates/updates as well as dynamic account-type expansion refreshes.

`account_types` is now managed from its own Sheet tab. Its 13 source columns, 14 database columns, bounded initial adoption and source/ingestion audit rules are documented in the [account-types mapping](account-types.md). Category synchronization only resolves those records and replaces category junctions; it does not generate account-type identities.

## Identity, constraints and mapping limits

- Unique classification: `(tx_type_key, major_category_key, minor_category_key)`. Upserts use the Sheet UUID. A different UUID cannot take over an existing classification; the row fails on the unique constraint.
- Once transactions or subscriptions reference a category, classification key changes fail until dependencies are explicitly reconciled; label/description changes remain allowed. Deleted dependent records still count as references.
- `source_account_mandatory`, `target_account_mandatory` and eligibility flags are stored. They do not turn into variable database nullability: see the [transaction](transaction-master.md) and [subscription](subscription-master.md) mapping gaps.
- Lists are not stored as source text, so original token order, duplicate hints and whether a broad hint or individual subtype hints were used cannot be reconstructed exactly from junction rows.
- The transform produces an in-memory `natural_key` string for classification, but no `natural_key` column exists in `category_master` and no checksum row is written.
