# Ledger extraction review — 2026-09-23

Reviewed the supported path from the four current GAS master tabs through validation, transformations, relational writes, and Sheet acknowledgements. Changes are local code/documentation; no live extraction or migrations were performed.

## Validation

Tests include offline GAS-schema contract comparison, raw Sheets snapshots and sparse pagination, duplicate UUIDs, source edit/ack failures, status/checkpoint failure paths, money/DST boundary cases, and a real disposable PostgreSQL migration/lifecycle pipeline.

PostgreSQL tests use private Unix sockets with TCP disabled, per-test disposable databases, and no `.env` credentials. They cover all currency and ledger migrations, row/group rollback, stable IDs, restores, transfer integrity, optional subscription dates, account/transaction FX correction and replay, legacy-rate NULL semantics, referenced category changes and full-job rerun/recovery. ## Remaining boundaries and adoption

- No live Google API smoke test or existing-data reconciliation was performed. Fixture tests cannot prove service-account permissions, actual Sheet formatting or all existing source rows are compatible.
- Sheets acknowledgements and PostgreSQL commits cannot be atomic across systems. Source rechecks reduce stale acknowledgement risk but cannot eliminate a human edit in the final check/write window. Use a quiet editing window; retry failed acknowledgements.
- The six account-detail tabs still need a separate mapped extraction design. Existing seven-table detail histories are not rebuilt or corrected here and should not be treated as maintained balances.
- Source removed rows are not automatically deleted. Source tombstones are required. In-sync rows are not compared by content hash; source edits must queue a sync or be replayed explicitly.
- Account FX still permits the latest earlier rate without a maximum-age threshold; transaction FX requires exact UTC dates. Crypto gaps therefore remain actionable import failures. These policies are documented, not silently changed.
- Existing invalid immutable account history must be reconciled explicitly; old applied-rate snapshots remain NULL until replay. Already-corrupted prior detail/timestamp/history data is not automatically guessed or rewritten.
- Apply pending migrations 0011–0013 through the normal reviewed run workflow. A reviewed `--reprocess` run can repopulate supported rows and applied-rate snapshots; it may surface missing historical rates or source validation failures. No live run is part of this review.
