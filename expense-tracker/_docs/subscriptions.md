# Subscriptions

A registry of recurring payment obligations tracked in the app. Subscriptions represent future commitments — services, memberships, or any recurring charge — rather than actual spend. They are distinct from transactions: a subscription is never posted to an account balance and never affects Net Worth. It is a planning and awareness layer, not a ledger entry.

Schema reference: subscription-schema.gs, subscription-core.gs, subscription-validation.gs, subscription-utils.gs.

## Overview

Subscriptions differ from transactions in two fundamental ways:

1. **They are obligations, not events.** A subscription records that a payment _will_ recur on a schedule. The actual debit, when it occurs, is recorded as a separate transaction on the `transaction_master` sheet.
2. **Next payment date is computed, not stored.** The sheet holds the frequency, day anchor, optional boundaries and timezone. Quarterly/annual schedules also use the start month as their cycle anchor. `next_payment_date` is derived at read time by `computeNextPaymentDate()` and appended to the response object — it is never written to the sheet.

## Schema

21 columns, append-only positions.

| # | Field | Type | Editable | Description |
|---|---|---|---|---|
| 1 | `id` | string | No | System-generated UUID. Generated by `Utilities.getUuid()`. Globally unique; no date prefix, no counter. |
| 2 | `subscription_name` | string | Yes | User-facing display name for the subscription. Interactive create/update checks uniqueness across non-deleted subscriptions (case-insensitive, trimmed); CSV import uses UUID identity. |
| 3 | `counterparty_name` | string | Yes | Merchant, provider, or payee name. Optional. |
| 4 | `subscription_amount_local` | number | Yes | Recurring charge amount in the source account's local currency. Currency is derived by the server from the source account's `account_currency_local` — it is not stored on the subscription row. Must be a positive number. |
| 5 | `frequency` | enum | Yes | Recurrence cadence. Valid values: `weekly`, `monthly`, `quarterly`, `annual`. Determines which schedule anchor field is required. |
| 6 | `day_of_month` | number | Yes | Day of the month (1–31) on which payment falls. Required when `frequency` is `monthly`, `quarterly`, or `annual`. Values that exceed the month's length are clamped to the last day of that month at runtime. Normally blank for weekly; a supplied unused anchor is still validated and retained. |
| 7 | `day_of_week` | number | Yes | Day of the week (1=Monday … 7=Sunday). Required when `frequency` is `weekly`. Normally blank for other frequencies; a supplied unused anchor is still validated and retained. |
| 8 | `source_account` | string | Yes | Account ID (FK to `account_master.id`) from which the payment is drawn. Required. `list_subscriptions_view` returns the account name and currency for display. Also the source of the subscription's currency (via `account_currency_local` on the account). |
| 9 | `tx_type` | enum | Yes | Direction of the payment. Valid values: `money-in`, `money-out`. Optional; defaults to blank if not supplied. |
| 10 | `major_category` | string | Yes | Top-level category. Must come from a category where `is_subscription_eligible = true`. Optional. |
| 11 | `minor_category` | string | Yes | Sub-category under `major_category`. Optional. |
| 12 | `description` | string | Yes | Free-text notes. Optional. UI label: "Notes". |
| 13 | `record_status` | enum | Yes | Lifecycle state. Valid values: `active`, `inactive`, `deleted`, `locked`. Default on creation: `active`. Expiry affects the computed schedule, never the stored lifecycle. Updatable via `update_subscription` to `active` or `inactive` only (`invalid_record_status` is returned for any other value). |
| 14 | `created_at` | string | No | ISO 8601 UTC timestamp set at creation. |
| 15 | `sync_status` | string | No | Sync pipeline state. Valid values: `create-pending`, `update-pending`, `in-sync`, `create-failed`, `update-failed`. Set to `create-pending` on creation; advanced by `computeSyncStatus()` on each mutation. |
| 16 | `sync_date` | string | No | UTC timestamp of the latest sync outcome, including failures. Cleared by source mutations. |
| 17 | `sync_notes` | string | No | Notes written by the sync pipeline (e.g. error detail). Cleared on each mutation. |
| 18 | `updated_at` | string | No | ISO 8601 UTC timestamp of the last write. Stamped on both create and update. |
| 19 | `subscription_start_date_local` | string | Yes | Local timestamp (`YYYY-MM-DD HH:MM:SS`, optional fractional seconds). Its calendar date is the inclusive schedule lower bound. Required for quarterly/annual recurrence, whose month cycle is anchored here; optional for weekly/monthly. |
| 20 | `subscription_end_date_local` | string | Yes | Optional local timestamp. Its calendar date is the inclusive schedule upper bound. End before start fails validation; expiry never writes lifecycle changes. |
| 21 | `subscription_timezone_local` | string | Yes | Validated IANA timezone (e.g. `Europe/London`). Required whenever a boundary date exists. Undated weekly/monthly schedules may leave it blank and use the schema default `Europe/London` for calendar display only. |

## Frequency and schedule logic

| Frequency | Required schedule fields | Next occurrence |
|---|---|---|
| `weekly` | `day_of_week` (1=Monday through 7=Sunday) | Matching weekday on or after today/start date |
| `monthly` | `day_of_month` (1–31) | Matching day in each calendar month |
| `quarterly` | `day_of_month`, start timestamp and timezone | Matching day every three months, anchored to the start month |
| `annual` | `day_of_month`, start timestamp and timezone | Matching day every twelve months, anchored to the start month |

The schedule uses the row's timezone, with `Europe/London` only for undated rows whose zone is blank. Today and both boundary dates are inclusive. Day 31 clamps to the final day of shorter months; annual February 29 clamps to February 28 outside leap years. The start/end timestamps remain exact source values, but recurrence is a **calendar-date reminder**, not a time-of-day execution schedule.

Dates are local timestamps with seconds and optional up to six fractional digits. Explicit offsets and `Z` are not accepted; use the separate IANA timezone. Source writes canonicalize accepted timezone aliases/casing. Invalid dates, reversed boundaries and ambiguous/nonexistent daylight-saving wall times fail validation, matching ledger-sheet-extract. The server-side CSV import also accepts date-only boundaries (normalized to midnight), minute-only timestamps (seconds set to zero) and an ISO `T` separator before validation.

`list_subscriptions` returns every lifecycle state, including deleted rows needed for restore/export. It computes `next_payment_date`, `schedule_status` (`current`, `upcoming`, `expired`, `invalid`, `inactive`) and, for invalid active schedules, `schedule_error`. These are response-only fields. Inactive, locked and deleted rows have no next date. An expired row or a schedule with no remaining occurrence before its end also has no next date.

Reading subscriptions never changes their stored lifecycle or audit/sync values. An expired active record remains active in the Sheet and database; its schedule shows expired. Old rows missing required schedule information remain visible with an actionable schedule error.

## Lifecycle and synchronization

- Pause/resume explicitly changes `active ↔ inactive` through update.
- Delete creates a `deleted` tombstone; restore validates the row and returns it to `active`.
- Locked rows reject edits, delete and bulk replacement. Deleted rows require restore or an explicit CSV lifecycle change before interactive editing.
- Interactive update permits `active`/`inactive` lifecycle choices; bulk import accepts the full schema lifecycle set. Omitted or blank CSV status preserves an existing row's state; a new row defaults to active.
- Every successful mutation preserves `id`/`created_at`, advances pending sync status, clears old `sync_date`/`sync_notes`, and stamps `updated_at`.
- Direct Sheet business/lifecycle edits, including pasted blocks and the trailing date/timezone columns, queue the same pending sync state through `onEdit`. Metadata-only edits do not queue a row. Physical removal is not a database delete: sync a tombstone instead.

These changes require deploying the backend. Use hard-sync once for source edits made before the new edit hook was deployed; normal-sync then skips existing in-sync rows. The [ledger contract](../../data-synchronization/ledger-sheet-extract/_docs/subscription-master.md) defines database identity, conversion and acknowledgements.

## Account and category linkage

`source_account` is a required account UUID, preserved as the reference to `account_master.id`; it is never an account name. The linked account determines currency. New active obligations require an active account; existing historical references can be retained. Unknown UUIDs fail validation rather than entering the Sheet with a broken reference.

Direction and both category keys are independently optional. A complete triplet must resolve an existing category. Active source writes require an active, subscription-eligible category; historical lifecycle states may retain an existing inactive/deleted classification. Dropdowns read eligible categories from `get_subscription_form_options`. Partial classification remains partial and is preserved by the extractor with a null category FK; no category is invented.

The transaction screen's existing-subscription hint compares nondeleted definitions by counterparty, account and any supplied classification keys. It does not use the removed subscription tags field. This is a suggestion heuristic, not a persisted link between a payment and a subscription.

## Frontend behavior

The Subscriptions tab renders `list_subscriptions_view`: the server filters (status, major category, frequency, search), sorts, pages, computes `next_payment_date`, `due_in_days` and `schedule_status`, converts amounts and returns the summary; the browser only formats them. Form choices (accounts, eligible categories, frequencies, day labels) come from `get_subscription_form_options`; the schema arrives in `get_app_context`. Export downloads the filtered list with `page_size=all`. The monthly figure is a gross estimate in the selected display currency: monthly amount, weekly × 52/12, quarterly ÷ 3, annual ÷ 12. It includes incoming and outgoing definitions, excludes inactive/expired/invalid schedules, and identifies unavailable conversions as partial rather than silently presenting a complete total. No subscription creates a transaction or changes a balance.

## API surface

All subscription endpoints are routed through the single `/exec` GAS endpoint.

| Action | Method | Description |
|---|---|---|
| `list_subscriptions_view` | GET | View model: filtered / sorted / paged rows with schedule fields, display labels, quote amounts, `allowed_actions`, summary (scheduled count, estimated monthly amount). |
| `get_subscription_estimate` | GET | Monthly estimate for chosen subscriptions: `ids` = comma-separated UUIDs, `none` for an empty choice, or blank for all active (scheduled) subscriptions. Returns `estimate` `{mode, considered_count, selected_ids, out_quote, in_quote, net_quote, missing_rate_count, missing_currencies, partial, ignored_ids}`. Unknown or unscheduled ids are listed in `ignored_ids`, never counted. |
| `get_subscription_form_options` | GET | Accounts, eligible categories, frequencies, day labels and the edited row (`id`). |
| `list_subscriptions` | GET | Raw rows, all lifecycle states, with computed schedule fields (kept for the ledger-sheet-load job's sheet-rebuild mode; the app does not call it). |
| `create_subscription` | POST | Validates identity, schedule and references, checks duplicate nondeleted names, and appends a row. |
| `create_subscriptions_bulk` | POST | Body `{ csv, dry_run? }` (raw file text) handled by `importSubscriptionsCsv`; see [CSV import](#csv-import-and-export). Format errors return `{ ok: false, error: 'invalid_csv_headers' \| 'invalid_csv' \| 'invalid_csv_rows', errors }` and write nothing. A real run does UUID-based insert/replacement via the internal `createSubscriptionsBulk` and returns `{ ok, created, updated, failed, results, rows }`; each result includes its zero-based `index`, CSV `line`, identity `key`, and success action or failure reason. |
| `update_subscription` | POST | Merges supplied editable fields with the existing row, validates the resulting record, then writes once. A pause/resume request needs only the row number and new lifecycle status. |
| `delete_subscription` | POST | Soft-deletes an unlocked row and queues sync. No other entity has a subscription FK. |
| `restore_subscription` | POST | Requires a deleted row, validates it, checks duplicate nondeleted names, and restores active lifecycle. An expired restored row still has no future payment date. |

### Validation failures

Responses use `{ ok: false, error: 'snake_case_code', field, message }`. `field` names the request field (e.g. `subscription_amount_local`, `day_of_month`, `subscription_end_date_local`) and `message` is human copy that the form shows as-is. The form does no validation of its own. `duplicate_subscription` currently has no `message`, and the form falls back to its own text. CSV import error lines append the field in brackets, e.g. `Row 2: id must be a UUID [id] (invalid_id).` Required values report `missing_name`, `missing_subscription_amount_local`, `missing_source_account`, `missing_frequency`, `missing_day_of_month`, `missing_day_of_week` or `missing_subscription_start_date_local`. Other useful codes include:

| Group | Examples |
|---|---|
| Identity | `invalid_id`, `duplicate_id_in_batch`, `invalid_existing_subscription_id`, `duplicate_existing_subscription_id` |
| Values | `invalid_subscription_amount_local`, `invalid_frequency`, `invalid_day_of_month`, `invalid_day_of_week`, `invalid_tx_type`, `invalid_record_status` |
| Dates | `missing_subscription_timezone_local`, `invalid_subscription_timezone_local`, `invalid_subscription_start_date_local`, `invalid_subscription_end_date_local`, `end_before_start`, `ambiguous_local_time`, `nonexistent_local_time` |
| References | `invalid_source_account`, `unknown_source_account`, `source_account_not_active`, `unknown_category`, `category_not_active`, `category_not_subscription_eligible` |
| Mutations | `record_locked`, `record_deleted`, `not_deleted`, `subscription_already_deleted`, `duplicate_subscription`, `duplicate_name`, `field_not_editable`, `missing_row_num`, `invalid_row` |

## CSV import and export

Required columns are `subscription_name`, `subscription_amount_local`, `frequency` and `source_account`. The frequency determines the required day anchor and whether a start timestamp is needed. Any supplied boundary needs `subscription_timezone_local`.

Optional business columns are `id`, `record_status`, `counterparty_name`, `day_of_month`, `day_of_week`, `tx_type`, `major_category`, `minor_category`, `description`, `subscription_start_date_local`, `subscription_end_date_local` and `subscription_timezone_local`. Export includes the full 21-column Sheet contract. Exported `created_at`/`updated_at` remain UTC audit values, not browser-local conversions. Import accepts sync/audit columns but ignores their values; the backend owns these fields. Response-only schedule fields are not exported to CSV.

The browser only reads the file and sends its raw text (`{ action: 'create_subscriptions_bulk', csv }`); `importSubscriptionsCsv` in `api/subscription-import.gs` parses and validates it (shared parsing in `api/csv-import.gs`). The parser handles a BOM, quoted commas, escaped quotes and multiline notes. Blank, duplicate, missing-required or unknown headers return `invalid_csv_headers`; malformed quoting returns `invalid_csv`. Every row is then checked with the same `validateSubscriptionCreate` used by interactive create (amount, frequency, day anchors, dates, timezone, `tx_type`, `record_status`, `id`/`source_account` UUID syntax), plus duplicate ids within the file. Any failing row returns `invalid_csv_rows` with `errors: ['Row <line>: …']` using physical CSV line numbers, and nothing is written. Numeric suffixes, grouping separators, infinity and hexadecimal amounts are rejected; decimal text is preserved exactly until ETL minor-unit conversion. UUIDs are lowercased; blank `id`/`record_status` are omitted; only business columns are forwarded to `createSubscriptionsBulk`.

`dry_run: true` runs the same parsing and format validation without reading or writing any Sheet and returns `{ ok, dry_run, rows }`. Sheet-dependent checks (unknown or inactive accounts, categories, locked rows) happen during the real run and are reported per row.

A supplied UUID identifies the row to insert or replace. Matching is case-insensitive; existing identity spelling and `created_at` survive retries. Missing IDs are generated. Re-import without IDs can create duplicates, so retain IDs for repeatable imports. Bulk import intentionally matches IDs rather than names, permits explicit lifecycle changes on unlocked rows, and preserves omitted lifecycle state. Invalid/duplicate identities already in the Sheet abort the import before data writes.

A real run returns the bulk result (`created`, `updated`, `failed`, `results[]`, `rows`) with every result carrying its CSV `line`. The panel shows `N created · N updated · N failed` and a table of line, error code and details for failed rows. There is no preview and no retry button: fix the file and import it again (rows with IDs are upserted, so re-importing is safe). A transport failure can leave an unknown outcome; check/reload the Sheet before submitting again, especially for rows without IDs.

The current local `local/files/subscription_master.csv` has 21 monthly definitions. Every row now has an explicit `subscription_timezone_local` (currently `Europe/London`). Zones are never inferred from account currency or the browser; a blank zone is rejected for dated rows.

## Existing data and deployment

Column positions remain unchanged at 21; all six lifecycle/sync/audit fields are present in their historical positions. Do not reorder a live tab to place them at the end. No new Sheet or database migration is required for this review; ledger migrations through 0022 remain required.

Deploy the updated backend and frontend together, reload the app, correct any displayed schedule/reference errors, and run dev hard-sync once. Invalid historical dates/zones are reported rather than guessed. Subscriptions remain planning definitions: there is no automatic payment posting, holiday adjustment, time-of-day execution or link to a generated transaction.

## Monthly estimate and choosing subscriptions

The summary card shows **Est. monthly payments** (outgoing subscriptions), plus monthly **Income** (money-in subscriptions) and **Net**, all converted to the quote currency on the server. By default it covers every active, scheduled subscription (`summary.estimate`, `mode: 'all_active'`).

**Choose subscriptions** turns on select mode: tap a card (phone) or row (desktop) to add or remove it. Only scheduled subscriptions can be chosen. A bar pinned to the bottom of the screen keeps the figure in view with **All active**, **Matching (n)** (when filters are applied: every scheduled subscription matching the filters across pages, from `selectable_ids`), **None** and **Done**. **Use all active** returns to the default.

The browser only keeps the chosen ids for the current visit (nothing is saved). Taps are batched for about half a second into one `get_subscription_estimate` request; the old figure stays dimmed with "updating…" until the new one arrives. On phones the list renders as cards.
